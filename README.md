# CMPT 310 — Multi-Label Clothing Classification

Multi-label image classifier that predicts four clothing attributes (color, season, type, usage) using Transfer Learning (ResNet50).

---

## Stack

- **Language:** Python 3.10+
- **Deep Learning:** TensorFlow / Keras (ResNet50)
- **ML / Data:** scikit-learn, NumPy, pandas
- **Image processing:** Pillow
- **Visualization:** Matplotlib
- **Demo (Milestone 2):** Gradio
- **Dataset:** Kaggle CLI (`kaggle`)
- **Notebooks:** Jupyter

## Setup

### 1. Create a Virtual Environment

Open a PowerShell terminal in the project folder, then run:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

To leave the virtual enviroment
```powershell
deactivate
```

### 2. Set Up Kaggle Credentials

1. Go to [kaggle.com](https://www.kaggle.com) → your profile → **Account** → scroll to **API** → click **Create New Token**
2. This downloads a file called `kaggle.json`
3. Move it to: `C:\Users\<your-username>\.kaggle\kaggle.json`
If directory does not exist create it!

### 3. Download the Dataset

With the venv active, run:

```powershell
kaggle datasets download -d paramaggarwal/fashion-product-images-small -p data/raw --unzip
```

This places `styles.csv` and an `images/` folder inside `data/raw/`.

**Dataset:** [Fashion Product Images (Small)](https://www.kaggle.com/datasets/paramaggarwal/fashion-product-images-small) — ~44,000 product images at 80×60 px with rich metadata.

| Column in `styles.csv` | Label used |
|------------------------|------------|
| `baseColour`           | color      |
| `season`               | season     |
| `articleType`          | type       |
| `usage`                | usage      |

### 4. Preprocess and Split the Dataset (V2 pipeline)

After downloading the Kaggle dataset, clean it:

```bash
python src/balance_clean_dataset.py
```

This script:

- Loads `data/raw/styles.csv`, keeps `Apparel` items with valid `baseColour`, `season`, `usage`
- **Consolidates colour shades** into 12 canonical colours (e.g. `Navy Blue` / `Teal` → `Blue`) via a `COLOR_MAP`
- **Deduplicates by image content** (SHA256 hash), and drops images whose duplicates have contradictory labels
- No longer downsamples by usage — the full cleaned dataset is kept (no artificial balancing)
- Saves `data/processed/clean_apparel_v2.csv`, plus reports in `reports/` (`v2_color_mapping.csv`, `v2_conflicting_duplicates.csv`, `v2_unreadable_images.csv`)

Then split it:

```bash
python src/preprocess_split.py
```

This script:

- Resizes images to `96x96` (aspect-ratio-preserving padding) into `data/processed/images_96_v2/` — used by the KNN baseline
- Creates a **stratified 70/15/15 train/val/test split** on colour×season×usage, pooling rare combinations so no class is missing from any split
- **Validates zero data leakage** (no shared `id` or image hash across splits)
- Keeps both the KNN-ready 96×96 path (`image_path`) and the full-resolution path (`raw_image_path`, used by the CNN) in every row

Generated files:

```text
data/processed/metadata_v2.csv
data/processed/train_v2.csv
data/processed/val_v2.csv
data/processed/test_v2.csv
data/processed/images_96_v2/
```

Split ratio:

```text
70% train
15% validation
15% test
```

Each CSV contains:

```text
id
image_path        (96x96, KNN-ready)
raw_image_path     (full resolution, CNN-ready)
sha256
baseColour
originalColour     (pre-consolidation colour)
season
usage
productDisplayName
split
```

Note: The `data/` folder is ignored by GitHub, so each team member needs to download the Kaggle dataset and run both scripts locally.

### 5. Train the KNN Baseline

With the venv active and the dataset downloaded, run these two scripts in order from the project root:

```powershell
python src/balance_clean_dataset.py
python src/KNN/knn.py
```

> **⚠ Known mismatch:** `balance_clean_dataset.py` now produces `data/processed/clean_apparel_v2.csv`
> (see step 4), but `knn.py` still hard-codes the old
> `data/processed/clean_colour_season_style.csv` path. On a machine where that old file was
> already generated before the V2 pipeline landed, `knn.py` still runs against it — but a fresh
> clone running only the current scripts will hit a `FileNotFoundError`. `knn.py` needs to be
> pointed at the V2 CSV (and retrained on it) as a follow-up; this hasn't been done yet.

`balance_clean_dataset.py` (see step 4 for its current, actual behaviour):
- Loads and cleans `data/raw/styles.csv`, saves the result to `data/processed/clean_apparel_v2.csv`

`knn.py`:
- Loads `data/processed/clean_colour_season_style.csv` *(stale path — see warning above)*
- Resizes each image to 96×96, flattens it, and encodes the `baseColour`, `season`, and `usage` labels
- Splits into train/test (80/20, stratified by `usage`), trains a `MultiOutputClassifier` wrapping `KNeighborsClassifier(k=5, weights="distance")`
- Prints exact-match accuracy plus per-label accuracy, weighted F1, and a classification report
- Saves the trained model to `models/KNN/knn_baseline.joblib`

#### About `knn_baseline.joblib`

A dictionary saved with `joblib.dump`, containing everything needed to reuse the trained model without retraining:

- `model` — the fitted `MultiOutputClassifier` (KNN) for `baseColour`, `season`, and `usage`
- `label_encoders` — a `LabelEncoder` per label, used to map predictions back to text
- `label_columns` — `["baseColour", "season", "usage"]`
- `image_size` — `(96, 96)`, the size images must be resized to before prediction

### 5.1 Use the train model

**Example: load the model and predict on a new image**
**Use the included script:** drop a test image into a `testingimgs/` folder in the project root, then run:

```powershell
python src/KNN/predict_knn.py testingimgs/your_image.jpg
```

This prints the predicted `baseColour`, `season`, and `usage` for that image.

### 6. Train and Evaluate the CNN (Milestone 2)

With the venv active and the dataset downloaded (steps 3–4 above), run these
scripts in order from the project root:

```powershell
python src/CNN/prepare_color_aux_dataset.py
python src/CNN/prepare_style_aux_dataset.py
python src/CNN/train_cnn.py
python src/CNN/evaluate_cnn.py
python src/CNN/app_gradio.py
```

`prepare_color_aux_dataset.py` (optional but recommended):
- Download the auxiliary colour dataset first: `kaggle datasets download -d imoore/6000-store-items-images-classified-by-color -p data/external/color_ds --unzip`
- Catalogs it into `data/processed/color_aux_v1.csv` — 5,889 colour-only images (11 of our 12 colour classes; `silver` has no match in our scheme and is dropped) used to supplement the weakest colour classes (Brown especially: +681 training images vs. our own 402)
- If this CSV doesn't exist, `train_cnn.py` just trains on the main dataset alone — this step is optional

`prepare_style_aux_dataset.py` (optional):
- No manual download needed — fetches directly from the HuggingFace `orianrivlin/fashion-lookmatch-dataset` datasets-server API and downloads images into `data/external/lookmatch_ds/`
- **Every image in this dataset is AI-generated** (Stable Diffusion XL from a text prompt), not a real photograph — a real domain gap from our own product photos, contained the same way as the colour data (see Phase 4 below)
- Keeps only apparel categories (jacket, hoodie, chinos, t_shirt, shirt, jeans, dress, skirt), dropping accessories/footwear (bag, watch, sneakers, boots) to match our own dataset's Apparel-only scope
- Derives a `usage` label from the source's free-form style tags: `formal` → Formal, else `sporty` → Sports, else (casual/smart_casual/vintage/streetwear/minimal) → Casual. No tag maps to Ethnic, so that gap stays open
- `season` is kept as-is when present (~73% of rows; genuinely balanced across all 4 seasons, unlike our own severely Spring/Winter-starved data)
- Catalogs 667 apparel rows into `data/processed/style_aux_v1.csv`

`train_cnn.py`:
- Loads `data/processed/train_v2.csv` / `val_v2.csv` and reads full-resolution images via the `raw_image_path` column (resized to 224×224 — ResNet50's expected input)
- Builds a **ResNet50** backbone (ImageNet weights) with **three softmax heads** — `color`, `season`, `usage` — a form of multi-task learning where one shared image encoder feeds three separate classifiers
- Trains in up to **four phases**: Phase 1 freezes the backbone and trains only the heads; Phase 2 unfreezes the top layers of ResNet50 and fine-tunes everything at a very low learning rate; Phase 3 (if `color_aux_v1.csv` exists) freezes everything except the colour head and polishes it on the merged colour data; Phase 4 (if `style_aux_v1.csv` exists) freezes everything except season/usage and polishes those on the merged style data
- Applies **class weights** per label (capped at 2.5×) so rare classes (e.g. Spring/Winter seasons, Formal usage) aren't ignored in favor of common ones, without over-correcting into the reverse problem (rare classes becoming a "cheap insurance" guess whenever the model is unsure)
- **Why separate phases, not joint training:** we first tried training the auxiliary colour data jointly with Phase 1/2 — it regressed season by 0.036 macro F1, because gradients from the auxiliary rows' colour loss still flow through the *shared* backbone even when season/usage loss is masked to 0 for those rows. Freezing everything except the target head(s) in a dedicated phase makes that structurally impossible instead of just less likely
- Each auxiliary row carries per-column `has_baseColour`/`has_season`/`has_usage` flags (defaulting to `True` for real data) so a head's loss is masked to exactly 0 for rows lacking that particular label — handles the style data's mixed case cleanly, where `usage` is always derivable but `season` is only present on ~73% of rows
- Auxiliary data is only ever merged into **training**, never validation/test, so evaluation numbers stay directly comparable across runs
- Saves the trained model to `models/CNN/resnet50_multitask.keras`, the label encoders to `models/CNN/label_encoders.joblib`, and the training history to `models/CNN/history.json`

`evaluate_cnn.py` (run after `train_cnn.py`):
- Loads the saved model and runs it on the held-out `data/processed/test_v2.csv`
- Prints accuracy, macro/micro F1, and a full precision/recall report **per label**
- Saves a confusion matrix PNG per label plus a training-curves PNG to `reports/`
- Prints a **KNN vs CNN comparison table**, scoring the saved KNN baseline (`models/KNN/knn_baseline.joblib`) on the same test images. Note: the KNN model was trained on the old 10-colour scheme, so test rows with colours it's never seen (Yellow/Beige/Orange) are excluded from the colour comparison only — the script prints exactly how many

`app_gradio.py` (run after `train_cnn.py`):
- Loads the trained model and launches a local Gradio web page
- Upload a clothing photo → get back predicted **color, season, and usage**, each with a confidence bar, plus a low-confidence review flag
- Prints a local URL (e.g. `http://127.0.0.1:7860`) — open it in a browser
